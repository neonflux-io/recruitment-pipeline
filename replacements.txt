# ── WORKFLOW: 01-candidate-intake ──────────────────────────────────────────────────────

# NOTE: The candidate intake trigger (01-candidate-intake) uses a generic Webhook node
# ("Webhook — Typeform"), NOT a Typeform OAuth2 node. No Typeform credential is required.
# The Typeform webhook URL is configured in Typeform Admin → Connect → Webhooks after
# activating 01-candidate-intake. The HMAC signing secret is set as an environment
# variable (TYPEFORM_HMAC_SECRET) — not a credential. See Step 2.5 and Step 5 in SETUP.md.

[TYPEFORM_HMAC_SECRET]
  → Your Typeform webhook signing secret (for HMAC-SHA256 verification).
  → Find it: Typeform Admin → Connect → Webhooks → your webhook → Signing Secret.
  → This is NOT a credential ID — it is the raw signing secret string.
  → Set as an n8n environment variable: n8n → Settings → Variables → + Add Variable
      Name:  TYPEFORM_HMAC_SECRET
      Value: <your signing secret>
  → The workflow reads it via $env['TYPEFORM_HMAC_SECRET'] — never hardcode it.

[TYPEFORM_FORM_ID]
  → Your Typeform form ID.
  → Find it: Typeform Admin → your form → Share → Copy link → extract the last path segment.
  → Example: https://yourworkspace.typeform.com/to/Ab1Cd2Ef → form ID is Ab1Cd2Ef.

[POSTGRES_CREDENTIAL_ID]
  → Your n8n Postgres credential ID.
  → Create in: n8n → Settings → Credentials → + New → Postgres → fill connection details.
  → Connection target: Supabase Postgres direct connection URL.
  → Find Supabase connection string: Supabase dashboard → Project → Settings → Database → Connection string (URI).
  → The URL format: postgresql://postgres:[PASSWORD]@db.[PROJECT_REF].supabase.co:5432/postgres

# Database schema — NOT a placeholder. The SQL query in "Postgres — Load Client Config"
# is pre-written and references three fixed table names: clients, scoring_prompts, email_templates.
# See SETUP.md Step 2.4 for the complete DDL to run in Supabase before activating.
# The slug column in the clients table is what maps to the Typeform client_slug hidden field.

# ── WORKFLOW: 03-crm-routing ────────────────────────────────────────────────────────────

[HUBSPOT_CREDENTIAL_ID]
  → Your n8n hubspotAppToken credential ID (HubSpot Private App Token).
  → Create in: HubSpot → Settings → Integrations → Private Apps → Create → grant scopes below.
  → Required scopes: crm.objects.contacts.write, crm.objects.contacts.read,
    crm.objects.deals.write, crm.objects.deals.read.
  → Then in n8n → Settings → Credentials → + New → HubSpot API → paste the token.
  → Used twice in 03-crm-routing (Contact Upsert + Deal Create nodes).

[HUBSPOT_DEAL_STAGE_ID]
  → Your HubSpot deal pipeline stage ID (e.g. 'appointmentscheduled').
  → Find it: HubSpot → Settings → CRM → Deals → Pipelines → click your pipeline → copy the Stage ID.
  → Common defaults: appointmentscheduled, qualifiedtobuy, presentationscheduled.
  → Replace the literal placeholder in node: "HubSpot — Deal Create" → stage parameter.

# ── WORKFLOW: 06-offer-gate ────────────────────────────────────────────────────────────

[OFFER_WEBHOOK_SECRET]
  → Shared HMAC-SHA256 signing secret between your recruiter dispatch system and this webhook.
  → Generate: openssl rand -hex 32  (or any 32+ character random string).
  → Your dispatch system signs the raw JSON body with this secret and sends the result in:
      Header: x-offer-signature: sha256=<hex>
  → Set as an n8n environment variable: n8n → Settings → Variables → + Add Variable
      Name:  OFFER_WEBHOOK_SECRET
      Value: <your generated secret>
  → The workflow reads it via $env['OFFER_WEBHOOK_SECRET'] — never hardcode it.
  → KEEP THIS SECRET — it is the only auth on the offer gate webhook.
  → Also include requestedAt (ISO string) in the JSON body to enable replay protection.
